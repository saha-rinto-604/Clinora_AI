# Clinora AI

Clinora AI is a role-aware healthcare platform for managing verified Patient information, medical reports, care coordination, and evidence-backed AI explanations. The application separates deterministic clinical facts from AI-generated language: verified values, ranges, dates, comparison eligibility, and evidence remain Clinora's source of truth.

Clinora is not a diagnostic system, and its AI output does not replace professional medical advice.

## Current Capabilities

### Patient workspace

- Account registration, email verification, sign-in, password recovery, sessions, and profile management
- Health Profile information, including Body & Vitals and recorded clinical context
- Private medical report upload, malware scanning, storage, viewing, download, metadata editing, archive, and restore
- OCR extraction with Patient correction and verification before observations become trusted facts
- Clinora AI Report Analyzer for grounded explanations of verified report observations
- Longitudinal Health Record with canonical measurements, comparable history, date-safe trends, evidence, and timeline views
- Personal Health Summary as a concise evidence-backed health briefing, with Gemini-assisted synthesis, deterministic changes, follow-up topics, visit questions, limitations, and PDF export
- Doctor discovery, profiles, appointment booking, appointment detail, and notifications
- Blood Network availability, nearby discovery, requests, responses, matching, status coordination, and map/route support when Google Maps is configured

### Doctor and professional access

- Doctor dashboard, profile, availability, schedule, and appointment workspace
- Patient-authorized report review and comparison within appointment workflows
- Doctor and Researcher application, email verification, status, interview, activation, and administrator access-review flows

There is no general Researcher data workspace in the current application; the implemented Researcher scope is professional-access onboarding.

## AI and OCR Responsibilities

### Report AI

Patient report explanations use the private Python AI service and a local MedGemma model served by llama.cpp. The service accepts verified structured observations, applies the current grounded response contract, and rejects unsupported evidence, diagnosis language, unsafe instructions, or invalid output. Raw report files and raw OCR text are not sent to the Report AI language-model request.

### Health Summary AI

Personal Health Summary language is generated by Gemini 2.5 Flash through the Spring backend. The API key stays server-side. Clinora first determines eligible verified facts, supplied-range status, reliable clinical dates, comparability, and longitudinal change; Gemini only prioritizes and explains that minimized structured evidence. Undated verified observations may inform the current health picture but cannot create chronological or trend claims.

If Gemini is unavailable or its response is invalid, the deterministic summary remains available. Only successful validated narratives are cached, and manual refresh requests a fresh generation.

### OCR

The OCR FastAPI service processes supported report documents with PaddleOCR, Tesseract, OpenCV, and PDF/image tooling. Extracted observations require Patient review and verification before they can become evidence for longitudinal records or AI explanations.

## Architecture

| Service | Responsibility | Local endpoint |
| --- | --- | --- |
| Frontend | React Patient, Doctor, public, and administrator experiences | `http://localhost:5173` |
| Backend | Spring APIs, security, persistence, orchestration, Gemini summary integration, and PDF generation | `http://localhost:8080` |
| OCR service | Report extraction and structured observation candidates | `http://localhost:8000` |
| Report AI service | Grounded Patient report interpretation | `http://127.0.0.1:8001` |
| llama.cpp | Local MedGemma inference used by the Report AI service | `http://127.0.0.1:8002` |
| PostgreSQL | Authoritative application data | `localhost:55432` -> container `5432` |
| MinIO | Private report and application-document object storage | `localhost:9000` (console `9001`) |
| RabbitMQ | Asynchronous work and STOMP broker relay | `localhost:5672` (management `15672`, STOMP `61613`) |
| Redis | Ephemeral caching and rate-limit support | `localhost:6379` |
| ClamAV | Malware scanning for private uploads | container network only (`3310`) |

The default Compose topology runs frontend, backend, OCR, PostgreSQL, MinIO, RabbitMQ, Redis, and ClamAV. Report AI remains a manual host process by default so it can reach the loopback-only llama.cpp server. An opt-in `container-ai` profile is retained for environments that supply a model server reachable from that container.

## Local Development

### Prerequisites

- Docker Desktop with Compose
- Java 21 and Maven for backend development
- Node.js 22 and npm for frontend development
- Python 3.12 for OCR and Report AI development
- A compatible llama.cpp `llama-server` and local MedGemma runtime for Report AI

### Environment setup

Copy `.env.example` to the repository-root `.env` on first setup, then replace development placeholders with local secrets. Never commit `.env`, API keys, tokens, passwords, model files, or generated Patient data.

For Gemini-assisted Health Summaries, configure `GEMINI_API_KEY`. The defaults in `.env.example` use `GEMINI_MODEL=gemini-2.5-flash` and the Google Generative Language `v1beta` base URL. The key is forwarded only to the backend container.

### Start the application

From the repository root:

```powershell
docker compose up -d
```

Use `docker compose up -d --build` after source or dependency changes. The backend and deterministic Patient Summary can start without the optional Report AI process or a configured Gemini key.

To enable local Report AI, first start llama.cpp:

```powershell
llama-server -hf gguf-org/medgemma-1.5-4b-it-gguf:Q4_0 --no-mmproj --device Vulkan1 --gpu-layers auto --fit on --parallel 1 -c 8192 --host 127.0.0.1 --port 8002
```

Then create the AI environment and run FastAPI:

```powershell
cd ai-service
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-medgemma.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8001 --log-level info
```

The root `.env` defaults `COMPOSE_AI_SERVICE_URL` to `http://host.docker.internal:8001`, allowing the Docker backend to call the host FastAPI process. See [ai-service/README.md](ai-service/README.md) for the model boundary and optional container profile.

`start-clinora-local.ps1` provides a Windows helper for starting and checking the default Docker services; `-Rebuild` rebuilds application images. It reports external AI readiness but does not launch or terminate the Windows llama.cpp or FastAPI processes.

### Health checks

```powershell
Invoke-RestMethod 'http://localhost:8080/actuator/health'
Invoke-RestMethod 'http://localhost:8000/health'
Invoke-RestMethod 'http://127.0.0.1:8001/health'
```

Open the application at `http://localhost:5173`. The FastAPI `/health` endpoint checks the process; `/ready` additionally requires the configured llama.cpp model server to be ready.

## Environment Variables

The checked-in `.env.example` is the canonical name/reference list. Important groups include:

- Core services: `DATABASE_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `RABBITMQ_*`, `REDIS_*`, `OCR_SERVICE_URL`, and `AI_SERVICE_URL`
- Authentication and security: `JWT_SECRET`, `AUTH_*`, `RATE_LIMIT_KEY_SECRET`, `OCR_INTERNAL_TOKEN`, and `AI_INTERNAL_TOKEN`
- Health Summary AI: `GEMINI_API_KEY`, `GEMINI_MODEL`, and `GEMINI_API_BASE_URL`
- Report AI: `COMPOSE_AI_SERVICE_URL`, `HF_MODEL`, `HF_MODEL_REVISION`, `AI_PROMPT_VERSION`, `AI_SCHEMA_VERSION`, `AI_MAX_NEW_TOKENS`, `LLAMA_SERVER_URL`, and timeout/concurrency settings
- Storage and scanning: `S3_*`, `S3_APPLICATION_*`, `MINIO_ROOT_*`, and `PATIENT_REPORT_MALWARE_*`
- Optional maps and local fixtures: `GOOGLE_MAPS_API_KEY`, `VITE_GOOGLE_MAPS_API_KEY`, and explicitly enabled development seed variables

Keep secret values only in local or deployment secret stores. Do not expose Gemini, storage, email, authentication, or internal-service credentials in frontend variables.

## AI Safety and Data Handling

- Patient-reviewed, verified Clinora observations are the evidence source for report and summary explanations.
- AI does not establish measurement values, reference status, chronology, or trends.
- Gemini receives minimized structured facts rather than Patient identity, contact details, raw OCR, original PDFs, filenames, storage keys, or session data.
- Missing or uncertain clinical dates do not become upload-date-based medical chronology.
- Generated statements must map back to allowed evidence; unsupported or malformed model output is rejected or pruned according to the relevant contract.
- Clinora explanations are informational and non-diagnostic.
